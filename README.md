# moneygo

一个中文、响应式的个人记账 Web 应用。保留原有的暖白、橙色与鼠尾草绿设计，支持手机和桌面。

## v0.5 · 证据关联、退款应收与对账

「账务核对」已接入真实本地账本，所有关系都需你明确确认，有审计记录并进入完整备份。

- **多份证据只记一次**：选择主记录和重复证据，保留原交易及来源；同金额只是候选，不自动合并。当前要求类型、金额与资金账户相同，日期可不同，按主记录计入。不同账户、多笔合计和组合支付尚不支持。
- **部分与跨月退款**：把实际到账的收入分配给原支出，支持多次退款与分配上限。个人消费在原购买月份扣减；账户现金仍按到账日期变化。退款申请仅是待办，不增加现金，也不提前扣减消费。
- **报销和垫付**：填写第三方应承担份额、材料状态和到期日，区分未收到的应收和真实到账。可分次确认回款；已分配回款不再计普通收入。不会联系他人、提交报销或进行转账。
- **同日终余额核对**：手动输入实际余额及日期，展示账本推导余额、差额和参与交易。历史交易改变会提示依据已变；不会自动造调整交易，零差额也不代表账单完整。
- **可解释口径**：概览可下钻个人消费、现金支出、普通收入、现金收入、全部当前应收与排除证据。个人收支差额不等于现金变化；沙盘改用关联后的个人净消费。
- **先保护后续修改**：已有关联的交易锁定金额、日期、方向和资金账户，先撤销依赖才能修改，备注及分类仍可编辑。撤销导入批次也检查这些关系，不静默删去后续操作。

这些是可操作的本地功能；自动化覆盖模型、交互逻辑和迁移。实际浏览器布局、文件选择器与读屏验收尚未完成，不把 DOM 桩测试称为浏览器验证。

## v0.4 起 · 真实 CSV 导入与可恢复证据

在「账单导入」选择你自己的 CSV / TSV 文件，明确指定来源、资金账户、日期、金额和方向列，先检查、预览，再选择入账。文件由当前浏览器读取，不上传原始账单。

- **先确认格式**：支持明确选择编码、分隔符和日期格式；可选择第一行为表头，或明确按无表头文件映射；不支持把前置说明行猜作表头。来源标识由你命名，不能仅凭文件名判断支付平台。支付渠道字段与实际资金账户分别保存。
- **预览再入账**：区分新增、同源重复、同一交易后续版本、相似候选、冲突和坏行。候选不会自动被合并；未知金额、日期、方向或状态不会被猜成有效交易。
- **重叠导入**：同源稳定交易 ID 优先；无 ID 时使用可解释的字段指纹和行次序，同一文件重复导入不再新增，同时保留文件内多笔相同金额、日期的真实消费。新的相似记录需要你明确选择。
- **状态与证据**：处理中和取消记录保留证据，不增加消费；状态后续变化需再次确认。映射后必要字段、来源、批次与变更记录随 JSON 备份保留，未选中的额外列和原始文件默认不保存。
- **恢复与隔离**：坏行与暂未确认的记录保留在核对区；修复后再预览。批次撤销检查后续修改，遇到依赖或手动修改时拒绝整批覆盖并展示冲突。
- **映射模板与覆盖**：可保存已确认的映射；表头改变时必须核对。覆盖日期只接受你明确确认的导出起止区间，不能由最早/最晚一笔交易推断完整性。
- **备份试恢复**：「数据备份」可在隔离副本校验备份及余额，不替换当前账本。校验成功只证明该文件在当前版本可读，不证明你已妥善保存文件或浏览器不会丢数据。

**这是通用映射式 CSV 导入，不是已验证的微信支付、支付宝或招商银行格式适配器。** 目前没有这三类真实脱敏样本，因此没有承诺平台字段、时间语义、交易 ID 稳定性、导出范围或退款含义兼容。Excel / PDF 不支持；需要先自行导出为可明确映射的 CSV。证据关联、手工确认退款和应收已在 v0.5 接入。信用卡账期、组合支付、多笔合计匹配等仍按 [120 项实施路线](ROADMAP.md) 开发，独立样例不算正式能力。

## 消费沙盘（v0.3 起）

在侧栏打开「消费沙盘」，用真实历史推演接下来三个完整自然月。它是透明的情景计算，不是消费保证，也不需要大模型。

1. **确认完整月份**：只勾选确实记全全部消费的过去月份。没有记录不自动等于零；若主动确认空月完整，则明确按零计算。最多取最近 6 个已确认、已结束的月份。
2. **建立基准**：每个支出分类在采用月份中的个人净消费总额（排除关联的重复证据，扣除已关联退款与第三方份额）÷ 月份数，四舍五入到整数分。未来三个月沿用相同分类月均。收入、转账、回收区、本月和未来交易不进入基准。
3. **排除偶发支出**：在基准来源中打开月份，勾选历史旅行、换手机等不想重复推算的支出。原账目不变，排除只影响所有方案共用的基准。
4. **设置方案**：最多 3 个独立方案，分类可沿用基准、按整数百分比调整（-100% 至 +1000%），或填每月预算 / 固定支出。预算与固定支出都替换该分类每月总额，不叠加历史均值。房租等可单独建分类。
5. **添加一次性计划**：只在选定月份额外增加一次。不要把同一笔消费同时计入月预算和一次性计划。
6. **比较**：查看三个月总额、与历史基准的差额和每月拆分。方案不创建真实交易，也不影响账户余额。可以分别清空方案、删除方案或重置整个沙盘，均不会删除真实账本。

没有确认历史时，基准为未知。手动设置的分类可以算出已设置小计，但未设置分类仍是未知，完整总额与差额显示「待补全」。若所有现有支出分类都明确填写月金额（含明确的 0），可以得到纯手动方案总额。仅 1–2 个月、历史较旧时都会提示局限。不会宣称识别年度季节性、给出概率区间或推算未来余额 / 收入。

模拟期根据打开页面时的本机日期，从下月开始滚动三个月。过期或超出模拟期的一次性计划保留但不计入；失效分类假设也保留并警告。未来日期的真实交易不会自动成为计划，请自行核对。修改真实历史、跨月到账后关联退款、第三方份额或排除项会重新计算基准；基准不是冻结快照。最多保存 120 个完整月确认、10,000 个排除标记，每方案 200 项分类调整与 100 个一次性计划。所有金额、日期、整数范围和累计安全边界均校验。

## 本地记账

- 手动新增、编辑收入和支出；金额按整数「分」记录，最多两位小数
- 账户管理、期初余额与由交易推导的账户余额
- 收支分类管理；被交易引用的账户 / 分类不能删除
- 账户间转账，双向调整余额，不计入消费、收入或月结余
- 按年月查看收支与分类占比，按备注、账户、类型和分类筛选
- 确认后删除交易，已删除交易保留在回收区，可跨刷新恢复
- 浏览器本地持久化，版本化格式、损坏数据保护与跨标签页冲突提示
- JSON 备份导出；恢复前校验、预览、明确确认，并保留恢复前账本供撤销
- 默认从空白账本开始；内置虚构样例在独立的 `demo.html`，不与真实账本混合

## 数据与隐私

**数据只保存在当前浏览器的 localStorage，不会上传，不跨设备同步，也没有云端备份。**

- 清理网站数据、无痕浏览、浏览器存储限制或更换域名可能导致数据丢失或不可用。请定期导出 JSON 备份。
- 备份包含全部账户、分类、交易、已删除交易、沙盘设置、导入来源和必要映射字段、证据关联、退款与应收、余额快照及本地审计，是未加密的财务数据，请妥善保管。不要把备份或真实账单提交到这个公开仓库。
- 应用没有远程字体、分析脚本、网络 API、银行连接、AI 服务、登录或服务器数据库。托管平台的访问控制和静态资源请求独立于本地账本。
- 账户余额是期初余额加全部已记交易后的结果，**不是银行实时余额**。期初余额不计收入。全部日期的交易都会影响账户余额，月度统计只按交易日期筛选。
- 删除的交易不会自动永久清除，也会进入备份。删除后，其账户和分类仍受到引用保护。
- 备份恢复会替换整个账本及其全部扩展，不做合并。有账务关系的完整备份采用 v4 封装；可选同时包含 v3 导入和 v2 沙盘扩展，仍可读取 v1 / v2 / v3 旧备份。恢复旧备份会清除其中没有的扩展，确认前会展示数量。旧版应用拒绝新结构，避免悄悄丢关系。浏览器内只保留最近一次恢复前的数据，请先导出文件，避免仅依赖本地撤销。
- localStorage 不加密。共享设备、同源脚本或浏览器扩展可能访问它，不适合需要多用户隔离、审计或合规存储的场景。
- 请在一个标签页中编辑。应用会检测已发生的其他标签页变更并阻止旧页面覆盖；localStorage 不是数据库，不提供并发事务保证。

## 范围与限制

当前真实账本支持人民币、手动收入 / 支出 / 转账，以及用户映射的 CSV 收入 / 支出导入。账户数量最多 100，分类 200，交易和已删除交易共 10,000 笔；单笔金额上限为 ¥9,999,999,999.99。浏览器存储容量也可能先达到上限，保存失败时不会将未保存的修改显示为成功。

微信支付、支付宝、招商银行专用流程仍是**独立的虚构样例演示**。真实账本已有通用 CSV 导入和手工确认退款关系；没有自动退款关联、信用卡专用账期或多币种换算。演示中的操作仅在当前页面内存中有效，刷新重置。

备份结构与恢复边界见 [BACKUP_FORMAT.md](BACKUP_FORMAT.md)。全量开发状态见 [ROADMAP.md](ROADMAP.md)。

## 本地运行

无运行时依赖或构建步骤，Node.js 22+ 用于测试：

```sh
npm run check
npm test
python3 -m http.server 8080 --directory dist
```

打开 `http://localhost:8080`。真实记账请使用 HTTP(S)；不要依赖 `file://` 的存储行为。静态托管时将 `dist/` 作为网站根目录。

## 文件结构

```text
dist/
  index.html    真实本地账本入口
  app.js        交互与渲染
  ledger.js     可独立测试的数据模型、计算、验证与备份
  scenario.js   消费沙盘的严格模型与确定性计算
  importer.js   CSV 解析、映射、同源证据、批次与隔离记录
  relations.js  账务证据、退款、应收与日终快照的确定性模型
  relations-ui.js / relations-ui.css  账务核对交互
  styles.css    响应式样式
  demo.html     独立虚构样例入口
  demo.js       原导入流程演示
tests/          无第三方测试依赖的 Node.js 测试
```

仓库仅包含应用代码与合成测试数据。请勿提交密钥、账号凭据或真实账单。
