# moneygo

一个中文、响应式的个人记账 Web 应用。保留原有的暖白、橙色与鼠尾草绿设计，支持手机和桌面。

## v0.22 · 待退款记录的到账复核（本地自动化已通过）

## v0.11 · 组合支付、合并扣款与实付口径

本地已接入，尚未发布。入口为「账务核对 → 购买组合」。

- **两种证据分别确认**：选择哪些原记录说明个人消费、哪些说明实际扣款；每一组都必须精确合计为确认实付。银行一笔 100 元与平台 30＋70 元明细可以组成一件事，各口径只计 100 元。两张账户共同支付 30＋60 元也可保留各自负担。
- **日期与原文保留**：个人消费按个人证据日期，账户变化按资金证据日期，跨月不挪动原记录。复核显示每月、各账户和已有余额快照的前后影响；原始金额、账户、来源和物理行仍可查看。
- **未知价格不猜**：原价和优惠可以为空；均已知时须满足原价减优惠等于实付。不会把优惠当收入或自动补齐差额。
- **候选只是线索**：在明确选出的最多 24 条范围内搜索金额组合，界面说明每组最多 6 条、最多 100 个结果和 10,000 个搜索节点。每组消费/资金来源可手动各选最多 20 条；搜索有截断或剩余差额时明确显示，不自动选中或入账。
- **修改先处理依赖**：资金专用证据不能再分配退款/应收；个人证据按原明细保留容量。本人转移、重复证据副本、已被其他组或信用费用/分期引用的记录会被拒绝。当前组合只读，需先解除后续依赖，再复核撤销并重新建立；没有伪装成可编辑的按钮。
- **失败不假装保存**：确认使用绑定完整账本的预览；保存失败保留草稿与原因，原确认失效，必须重做预览。组合不生成任何资金交易。完整备份、冻结月结与快照保存可独立重算的角色证明。

外层备份仍为 v4/v5/v6；首次组合或组合月结分别升级账务/整理内部版本到 3，旧应用会拒绝新内部格式。旧有效数据和历史证明保留，详见 [组合证据合同](COMPOSITE_EVIDENCE.md) 和 [备份结构](BACKUP_FORMAT.md)。

本批还加强了对已撤销关系历史的逐事件校验。审查发现旧验证器可接受手工篡改后、最终没有活跃关系的超额退款/回款或无效重复关联历史；新检查拒绝这些反例。正常操作的当前金额上限原本已有校验，本次发现不代表正常记账金额计算错误，也不构成防篡改或机构认可的审计保证。

## v0.9 · 信用义务、还款证据与完整分期

本地已接入，尚未发布；正式可访问版本以发布记录为准。

- **账户角色要明确**：分别确认现金账户、信用负债、受限资金或其他；没有填写的保持未知。按真实账户流水与选定截止日展示已知现金余额、卡债和信用账户正余额。授信额度不进入资产；信用账户正余额不当现金，未知角色时不显示完整现金总额。账本余额仍不是银行实时余额。
- **正式账单和估计分开**：正式应还金额须有完整账期、出账日、到期日和来源；估计允许未知值，但不作为正式应还预测。未出账证据按现有最新账期边界列出，不能冒充银行已确认的未出账余额。
- **还款只引用真实转移**：分配已有手工转账或已确认双边配对，单边收入不能充当完整还款。所有账单共享原转移容量，不得超分。跨月按转入原日期认定已记录到账；未来到账单独列，尚未分配的实际转移也可查看。分配不再产生消费或现金。
- **分期保留全部尾部**：填写完整各期日期、本金和费用，或用明确日期生成整数分均摊草案；余分分给前面的期次。三个月之外、过去未核销和费用未知的期次都保留，未知费用不是零。已确认计入正式账单的期次由账单义务替代，不叠加一次。
- **有重叠就不硬合计**：多个账单可能结转旧欠款；未关联的期次可能已在账单内，甚至已随账单还过。存在这些歧义时组合义务总额显示未知，不把逐行金额相加称作最低应还。当前不自动猜测结转、逾期利息、合同解除或银行已核实还清。
- **费用保留原交易**：为真实支出标明利息、手续费或服务费及相关账单/分期；显示原金额和既有个人消费影响，不再制造第二笔费用。
- **修改有依据**：新增、修改、删除和撤销都需当前版本核对、原因及明确确认。已分配的原转移、已入账期次和引用交易受依赖保护，导入撤销也先检查。失败不部分保存。

所有义务、角色和索引都是本地记录，不发起还款、银行查询或对外联系。角色口径是当前用户设定下的解释，日期只截取实际流水、到账和逾期检查，不重建旧时账户角色或旧合同版本。历史“对外现金”统计保留原金额，信用账户启用后明确标为全账户对外流水，另列现金角色账户的真实变动。

完整备份增加外层 v6 与内部版 1 的信用义务扩展，读取旧 v1–v5；旧应用拒绝 v6，避免悄悄丢弃义务记录。仍须自行妥善保存未加密备份。

- **两边明确配对**：在「账务核对 → 本人账户转移」选择现有转出支出和转入收入，必须等额、不同本人账户，并确认同一次真实资金搬运。保留原记录、原日期和导入证据；没有另一边时保持未知，不补造交易。手续费和后续现金消费仍单独记支出。
- **对外现金和账户变动分开**：已配对的本人转移不算个人消费、普通收入或对外现金收支。全部账户实际流入/流出仍保留两边各自的日期；跨月不会移动到同一天，转移本金只按转出日计一次。原始流水金额不会显示成零。
- **可撤销且保护后续关系**：配对和解除均需明确确认及理由；关联后不能先改金额、账户、日期、方向或回滚依赖导入批次。原有备注/分类整理不被无故锁住，备份保存双边签名与审计。
- **差额只给核对方向**：余额快照的候选仅列能精确解释所选差额的已知账本假设，并展示依据和未知范围；候选分页可完整到达。不会自动调账，不把差额为零说成账单完整。
- **旧月结保留原口径**：旧封存继续保留；新封存可记录双边签名与原日期，后来配对/解绑可比较当时和现在的差异。商户页面分别展示原流水、对外现金和转移本金。

这不执行转账、提现或还款，也不证明银行资金在途状态。信用卡账期和分期模块仍另行实施。账务关系与整理扩展内部版本升级为 2，仍读取其旧版 1；外层完整备份仍为 v4/v5，旧应用会拒绝未知内部版本而不会丢弃新关系。

## v0.7 · 多文件队列与覆盖日历

本地开发已接入多文件选择/拖放；公开部署版本以发布记录为准。

- 一次选择最多 20 份 CSV/TSV、合计 32 MiB；每份最多 8 MiB，按打开顺序逐个实际读取。每份文件独立确认来源、资金账户、映射与入账选择，一个失败不覆盖其他草稿。
- 成功提交只处理当前文件，其余预览在账本变化后失效，必须重新核对。队列移除仅丢弃当前页面草稿，不删除已入账交易；撤销仍走原有依赖保护。刷新会清空未提交队列，完整备份不包含这些临时草稿。
- 按来源和资金账户展示月度覆盖日历，以文字/符号区分已确认、重叠和未确认日期。只采用有效批次的明确导出区间；无交易日不被推断成缺档或零消费。
- 下次导出清单保留所选月份早期缺口，不因为后来有新截止日就隐藏旧空档；明确排除和未声明的来源分别显示，处理中/待核对行不当作已完成。

没有添加自动提醒、固定导出周期或已验证的微信/支付宝/招商银行操作指引；这些仍有单独的验收缺口。

## v0.6 · 规则、商户与可回看的月结

「整理复盘」将重复整理和例外核对接入真实账本。

- **规则先试跑**：按备注文字、来源、账户、方向、整数金额范围和日期匹配，展示每条命中依据；不运行正则或代码。冲突必须明确优先级，预览默认不勾选，只有你选中的行才应用。保存规则不自动改历史。
- **商户原文保留**：用完整原始备注的精确匹配设置别名，可限定来源和账户。分析用的商户名另存，不覆盖原始备注或导入证据；具体门店不会因泛化关键词自动合并。
- **批量操作可核对**：保存命中的规则快照、交易前后值和批次；撤销先检查后来编辑、删除或别名变更，有冲突则整批不执行。存储失败后原账不变，需重新试跑再确认。
- **把核对顺序说清楚**：待导入、可能重复、待退款、未收回应收和余额差异按可解释的影响范围排序；可手动设顺序和延后日期。金额上限不是损失预测，延后不算问题已解决。
- **范围与新鲜度**：明确声明来源/账户的纳入或排除及理由。已确认的导出区间、尚待处理的行、未知来源范围和余额核验日期分别展示；日期覆盖齐全不代表账务已完整。概览和沙盘旁显示这些条件，范围披露不会自动筛除交易。
- **月末封存**：保存当时全月有效主记录、商户、分类名称、来源和财务影响，后来补账或退款可对比当前与封存及逐笔差异。旧版本不覆盖；不冻结银行余额，也不声称保存了未采集的经济活动。

新扩展进入 v5 完整备份，旧 v1–v4 仍可读取。规则和封存容量受浏览器限制；大账本检查可能需要数秒，不能把支持上限当成任意设备性能保证。

## v0.5 · 证据关联、退款应收与对账

「账务核对」已接入真实本地账本，所有关系都需你明确确认，有审计记录并进入完整备份。

- **多份证据只记一次**：选择主记录和重复证据，保留原交易及来源；同金额只是候选，不自动合并。当前要求类型、金额与资金账户相同，日期可不同，按主记录计入。不同账户、多笔合计和组合支付尚不支持。
- **部分与跨月退款**：把实际到账的收入分配给原支出，支持多次退款与分配上限。个人消费在原购买月份扣减；账户现金仍按到账日期变化。退款申请仅是待办，不增加现金，也不提前扣减消费。
- **报销和垫付**：填写第三方应承担份额、材料状态和到期日，区分未收到的应收和真实到账。可分次确认回款；已分配回款不再计普通收入。不会联系他人、提交报销或进行转账。
- **同日终余额核对**：手动输入实际余额及日期，展示账本推导余额、差额和参与交易。历史交易改变会提示依据已变；不会自动造调整交易，零差额也不代表账单完整。
- **可解释口径**：概览可下钻个人消费、现金支出、普通收入、现金收入、全部当前应收与排除证据。个人收支差额不等于现金变化；沙盘改用关联后的个人净消费。
- **先保护后续修改**：已有关联的交易锁定金额、日期、方向和资金账户，先撤销依赖才能修改，备注及分类仍可编辑。撤销导入批次也检查这些关系，不静默删去后续操作。

这些是可操作的本地功能；自动化覆盖模型、交互逻辑和迁移。实际浏览器布局、文件选择器与读屏验收尚未完成，不把 DOM 桩测试称为浏览器验证。

## v0.4 起 · 真实 CSV 导入与可恢复证据

在「账单导入」选择你自己的 CSV / TSV 文件，明确指定来源、资金账户、日期、金额和方向列，先检查、预览，再选择入账。文件由当前浏览器读取，不上传原始账单。

- **先确认格式**：支持明确选择编码、分隔符和日期格式；可明确选择表头或第一条数据的物理起始行；跳过前置说明需审阅并确认，不自动猜测。来源标识由你命名，不能仅凭文件名判断支付平台。支付渠道字段与实际资金账户分别保存。
- **预览再入账**：区分新增、同源重复、同一交易后续版本、相似候选、冲突和坏行。候选不会自动被合并；未知金额、日期、方向或状态不会被猜成有效交易。
- **重叠导入**：同源稳定交易 ID 优先；无 ID 时使用可解释的字段指纹和行次序，同一文件重复导入不再新增，同时保留文件内多笔相同金额、日期的真实消费。新的相似记录需要你明确选择。
- **状态与证据**：处理中和取消记录保留证据，不增加消费；状态后续变化需再次确认。映射后必要字段、来源、批次与变更记录随 JSON 备份保留，未选中的额外列和原始文件默认不保存。
- **恢复与隔离**：坏行与暂未确认的记录保留在核对区；修复后再预览。批次撤销检查后续修改，遇到依赖或手动修改时拒绝整批覆盖并展示冲突。
- **映射模板与覆盖**：可保存已确认的映射；表头改变时必须核对。覆盖日期只接受你明确确认的导出起止区间，不能由最早/最晚一笔交易推断完整性。
- **备份试恢复**：「数据备份」可在隔离副本校验备份及余额，不替换当前账本。校验成功只证明该文件在当前版本可读，不证明你已妥善保存文件或浏览器不会丢数据。

**这是通用映射式 CSV 导入，不是已验证的微信支付、支付宝或招商银行格式适配器。** 目前没有这三类真实脱敏样本，因此没有承诺平台字段、时间语义、交易 ID 稳定性、导出范围或退款含义兼容。Excel / PDF 不支持；需要先自行导出为可明确映射的 CSV。证据关联、手工确认退款和应收已在 v0.5 接入。信用卡账期、组合支付、多笔合计匹配等仍按 [120 项实施路线](ROADMAP.md) 开发，独立样例不算正式能力。

## 消费沙盘（v0.3 起）

在侧栏打开「消费沙盘」，用真实历史推演接下来三个完整自然月。它是透明的情景计算，不是消费保证，也不需要大模型。

1. **确认完整月份**：只勾选确实记全全部消费的过去月份。没有记录不自动等于零；若主动确认空月完整，则明确按零计算。最多取最近 6 个已确认、已结束的月份。
2. **建立基准**：每个支出分类在采用月份中的个人净消费总额（排除关联的重复证据，扣除已关联退款与第三方份额）÷ 月份数，四舍五入到整数分。未来三个月沿用相同分类月均。收入、转账、回收区、本月和未来交易不进入基准。
3. **排除偶发支出**：在基准来源中打开月份，勾选历史旅行、换手机等不想重复推算的支出。原账目不变，排除只影响所有方案共用的基准。
4. **设置方案**：最多 3 个独立方案，分类可沿用基准、按整数百分比调整（-100% 至 +1000%），或填每月预算 / 固定支出。预算与固定支出都替换该分类每月总额，不叠加历史均值。房租等可单独建分类。
5. **添加一次性计划**：只在选定月份额外增加一次。不要把同一笔消费同时计入月预算和一次性计划。
6. **比较**：查看三个月总额、与历史基准的差额和每月拆分。方案不创建真实交易，也不影响账户余额。可以分别清空方案、删除方案或重置整个沙盘，均不会删除真实账本。

没有确认历史时，基准为未知。手动设置的分类可以算出已设置小计，但未设置分类仍是未知，完整总额与差额显示「待补全」。若所有现有支出分类都明确填写月金额（含明确的 0），可以得到纯手动方案总额。仅 1–2 个月、历史较旧时都会提示局限。不会宣称识别年度季节性、给出概率区间或推算未来余额 / 收入。

模拟期根据打开页面时的本机日期，从下月开始滚动三个月。过期或超出模拟期的一次性计划保留但不计入；失效分类假设也保留并警告。未来日期的真实交易不会自动成为计划，请自行核对。修改真实历史、跨月到账后关联退款、第三方份额或排除项会重新计算基准；基准不是冻结快照。最多保存 120 个完整月确认、10,000 个排除标记，每方案 200 项分类调整与 100 个一次性计划。所有金额、日期、整数范围和累计安全边界均校验。

## 数据与隐私

**数据只保存在当前浏览器的 localStorage，不会上传，不跨设备同步，也没有云端备份。**

- 清理网站数据、无痕浏览、浏览器存储限制或更换域名可能导致数据丢失或不可用。请定期导出 JSON 备份。
- 备份包含全部账户、分类、交易、已删除交易、沙盘设置、导入来源和必要映射字段、证据关联、退款与应收、余额快照、分类规则、商户别名、冻结月结、信用义务/分期/还款分配/费用索引及本地审计，是未加密的财务数据，请妥善保管。不要把备份或真实账单提交到这个公开仓库。
- 应用没有远程字体、分析脚本、网络 API、银行连接、AI 服务、应用内登录或服务器数据库。托管平台的访问控制和静态资源请求独立于本地账本。
- 账户余额是期初余额加全部已记交易后的结果，**不是银行实时余额**。期初余额不计收入。全部日期的交易都会影响账户余额，月度统计只按交易日期筛选。
- 删除的交易不会自动永久清除，也会进入备份。删除后，其账户和分类仍受到引用保护。
- 备份恢复会替换整个账本及其全部扩展，不做合并。有整理复盘的完整备份采用 v5 封装；可选同时包含 v4 账务关系、v3 导入和 v2 沙盘扩展，仍可读取 v1 / v2 / v3 / v4 旧备份。有信用义务的备份采用 v6，包含其全部本地审计和引用；可读取 v1–v5。恢复旧备份会清除其中没有的扩展，确认前会展示数量。旧版应用拒绝新结构，避免悄悄丢关系。浏览器内只保留最近一次恢复前的数据，请先导出文件，避免仅依赖本地撤销。
- localStorage 不加密。共享设备、同源脚本或浏览器扩展可能访问它，不适合需要多用户隔离、审计或合规存储的场景。
- 请在一个标签页中编辑。应用会检测已发生的其他标签页变更并阻止旧页面覆盖；localStorage 不是数据库，不提供并发事务保证。

## 范围与限制

当前真实账本支持人民币、手动收入 / 支出 / 转账，以及用户映射的 CSV 收入 / 支出导入。账户数量最多 100，分类 200，交易和已删除交易共 10,000 笔；单笔金额上限为 ¥9,999,999,999.99。浏览器存储容量也可能先达到上限，保存失败时不会将未保存的修改显示为成功。

微信支付、支付宝、招商银行格式均未经过真实脱敏样本验证。应用提供通用 CSV 映射和手工确认退款关系，没有银行自动同步或多币种换算；本地信用义务以用户确认的信息为准。`demo.html` 使用同一正式程序和合成练习文件，内容只在当前文档内存中，刷新或重置会丢弃本次修改。它不证明平台兼容性。

备份结构与恢复边界见 [BACKUP_FORMAT.md](BACKUP_FORMAT.md)。全量开发状态见 [ROADMAP.md](ROADMAP.md)，具体已发布范围和未完成项见 [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md)。
